## 1. 项目概览

**定位**：本地优先、AI 辅助的个人工作日志与周报工具（macOS 桌面应用）。

**核心链路**：统一输入框记录 → AI 转化为结构化记录（含流程图）→ 热力图/日历可视化 → 一键生成周报 → WebDAV 云盘同步备份。

**技术栈（已定，实际采用）**

| 维度 | 选型 |
|---|---|
| 平台 | 仅 macOS |
| 框架 | Tauri 2（Rust 后端 + Web 前端） |
| 前端 | React 18 + TypeScript + Vite（组件内 `useState`/`useEffect` 管理状态，**未引入** Zustand）；流程图 Mermaid（懒加载） |
| 本地存储 | 文件化 JSON（按日），**纯文件化、无 SQLite**（索引为可选后续优化项） |
| 大模型 | OpenAI 兼容协议（`/chat/completions`）+ 本地 Ollama |
| 同步/备份 | WebDAV（多账号，坚果云 / InfiniCLOUD / 其他），仅备份结构化记录与周报 |
| 密钥 | macOS Keychain（API Key / WebDAV 密码，失败降级明文） |
| 认证 | HTTP Basic + Digest 自动适配（坚果云 Basic、中国科技云 Digest） |
| 配色 | 清新蓝白（主色 `#378ADD`，见原型） |

## 4. 核心模块设计

### 4.1 数据层 storage（`storage.rs`）
- **记录存储**：`{数据根目录}/records/YYYY/MM/YYYY-MM-DD.json`，每天一个文件，内容为当日全部 entries。
- **原子写入**：`serde_json::to_string_pretty` 后整体 `fs::write`（写入前 `create_dir_all` 父目录）。
- **核心类型**：`DayRecord { version, date, entries }`；`RecordEntry { id, createdAt, updatedAt, rawText, sourceAttachments, modelUsed, status, structured }`。
- **命令**：`get_day_record` / `save_day_record` / `confirm_record`（追加一条已确认记录）/ `get_month_active` / `get_year_active`（供日历/热力图统计每日条数）。
- **附件**：一次性原料——仅交 AI 转化，不入库引用、不落 `attachments` 目录参与备份；按「附件临时副本」策略清理。
- **数据根目录**：`~/Library/Application Support/WorkTrace/`（`lib.rs::data_dir()` 创建）。

### 4.2 AI 编排 ai（`ai.rs`）
- `chat_completion(model_id, system, user)`：通用 OpenAI 兼容对话调用（`POST {base}/chat/completions`，Bearer 鉴权，`temperature 0.3`）。
- `transform_record`：记录转化命令，解析模型返回的 JSON（兼容 ` ```json ` 代码块包裹）。
- `test_model`：连通性测试（发 `ping` 最小请求、`max_tokens 5`）；API Key 为空时从已保存配置回填。
- API Key 从 Keychain 读取（`settings::get_model` 回填），不落盘。

### 4.3 附件解析 parser（`parser.rs`）
- `parse_attachment(filename, base64_data, model_id)`：按扩展名分发。
- **Word（.docx）**：`zip` 解包 + `quick-xml` 提取 `word/document.xml` 中 `<w:t>` 文本（`<w:p>` 换行）。
- **PDF**：写临时文件后用 `pdf-extract` 提取文本层；扫描件（无文本层）提示需图片识别。
- **图片**：走视觉模型多模态消息（`image_url` + base64 data URL），识别文字与流程图（Mermaid）。
- 注意：`quick-xml 0.31` 的 `read_event()` 无 `buf` 参数。

### 4.4 同步引擎 sync（`sync.rs`）
- **客户端**：基于 `reqwest`（`rustls-tls`），支持 `PROPFIND` / `PUT` / `GET` / `MKCOL`。
- **认证自适应**：先尝试 Basic，收到 `401 + WWW-Authenticate: Digest` 时自动切换 Digest 重试（MD5 + qop=auth，`md5` crate 计算摘要），兼容坚果云（Basic）与中国科技云（Digest）。
- **增量同步**：`PROPFIND Depth:infinity` 列出远端，按相对路径 + `getlastmodified`（RFC 2822，chrono 解析）与本地 mtime 对比，上传本地新增/更新、下载远端新增/更新。
- **首次同步**：远端 `worktrace/` 目录不存在（404）时，`ensure_base` 逐级 `MKCOL` 自动建目录，视为空远端。
- **同步范围**：`records/`、`reports/` 两个目录；**不含附件、不含含密钥的 settings**。
- **时机**：启动（延迟 3s）、定时（每 60s 检查一次、累计到配置间隔触发）、退出（`RunEvent::Exit`，10s 超时）、手动（`sync_now`）。
- **超时保护**：reqwest 客户端 `connect_timeout 10s` + `timeout 30s`，避免网络异常挂起导致应用卡死。
- **账号测试**：`test_webdav` 发 `PROPFIND Depth:0`，区分 2xx 成功 / 404（目录待建）/ 401（认证失败）。
- **回归测试**：`#[cfg(test)]` 内 `test_parse_gmt_date`、`test_parse_propfind_jianguoyun`。

### 4.5 周报 report（`report.rs`）
- `generate_report(week_start, model_id)`：汇总本周 7 天 entries → 调 AI 生成四板块 Markdown → 存 `reports/YYYY-Www.md`。
- `export_report(content, week_start, format)`：Markdown → 简单 HTML（Word 命名空间头）→ 存 `.doc`（Word/WPS 可开）或 `.html`（浏览器打印存 PDF）。**当前为轻量导出，非原生 .docx/.pdf**（见 §9 待办）。

### 4.6 配置与密钥 settings（`settings.rs`）
- `ModelConfig`（大模型）、`WebdavConfig`（备份账号）、`BackupSettings`（全局同步设置）三类结构。
- 密钥存 Keychain：API Key 键 `model:{id}`、WebDAV 密码键 `webdav:{id}`；`set_secret` 失败降级明文存 JSON（保证功能可用）。
- **多备份账号**：`webdavAccounts: Vec<WebdavConfig>`（含 `id/name/provider/url/account/isDefault`），支持增删改查、设为默认；同步取「默认账号」（无默认取第一个）。
- **数据迁移**：旧版单账号 `webdav` 字段经 `LegacyWebdavConfig` 反序列化，`load()` 时自动迁移为「首账号 + 全局 `backup` 设置」并写回。

### 4.7 可视化（前端）
- 热力图：53 周 × 7 天网格，活跃度加权，可切年份、悬停显示条数。
- 日历：月视图，点击日期弹当日详情（DetailModal）；与热力图联动。
- 流程图：FlowDiagram 动态 `import("mermaid")` 按需加载，主 bundle 显著减小。

## 5. 数据模型

### 5.1 每日记录 `records/2026/08/2026-08-16.json`

```json
{
  "version": 1,
  "date": "2026-08-16",
  "entries": [
    {
      "id": "uuid",
      "createdAt": "2026-08-16T12:40:00+08:00",
      "updatedAt": "2026-08-16T12:45:00+08:00",
      "rawText": "今天和产品对了需求，输出 PRD 初稿",
      "sourceAttachments": [],
      "modelUsed": "deepseek-chat",
      "status": "confirmed",
      "structured": {
        "summary": "与产品对齐需求并输出 PRD 初稿",
        "tasks": ["需求评审会议", "输出 PRD 初稿"],
        "tags": ["文档", "沟通"],
        "outputs": ["PRD 初稿 v0.1"],
        "flowcharts": [
          { "title": "需求评审流程", "mermaid": "graph LR; A[需求评审] --> B[确认通过] --> C[输出PRD]" }
        ],
        "todos": ["根据评审意见修订 PRD"]
      }
    }
  ]
}
```

字段说明：`status` 取值 `pending`（待确认）/ `confirmed`（已确认）/ `edited`（用户改过）；`flowcharts` 可空数组；`sourceAttachments` 当前为空数组（附件作一次性原料，不存引用）。

### 5.2 周报 `reports/2026-W33.md`

```json
{
  "weekStart": "2026-08-10",
  "weekEnd": "2026-08-16",
  "generatedAt": "2026-08-16T12:45:00+08:00",
  "modelUsed": "deepseek-chat",
  "content": "# 周报……（四板块 Markdown）"
}
```

### 5.3 应用设置 `settings/app.json`（密钥不入此文件）

```json
{
  "models": [
    { "id": "uuid", "name": "DeepSeek-V3", "baseUrl": "https://api.deepseek.com/v1",
      "model": "deepseek-chat", "role": "record", "isDefault": true }
  ],
  "webdavAccounts": [
    { "id": "uuid", "name": "坚果云", "provider": "jianguoyun",
      "url": "https://dav.jianguoyun.com/dav/", "account": "user@example.com",
      "isDefault": true }
  ],
  "backup": { "syncIntervalMin": 5, "attachmentRetentionDays": 7 }
}
```

> `apiKey` / `password` 存 macOS Keychain（键 `model:{id}` / `webdav:{id}`），JSON 中为空字符串或 Keychain 写入失败时的降级明文。`role` 取值 `record`（记录转化）/ `report`（周报生成）/ `vision`（图片识别）。

## 6. AI 转化 Prompt 规范

**记录转化系统提示词**（`ai.rs::SYSTEM_PROMPT`）：

```
你是工作日志结构化助手。把用户的工作记录（可能包含文字、从 Word/PDF 提取的文本、图片内容说明）
转化为结构化 JSON。只输出一个合法 JSON 对象，不要输出任何其他文字、注释或 Markdown 代码块。

输出 Schema：
{
  "summary": "一句话摘要，说明做了什么，不超过 30 字",
  "tasks": ["拆分出的具体事项，动词开头，每项一句话"],
  "tags": ["分类标签"],
  "outputs": ["交付的产出物或成果"],
  "flowcharts": [{"title": "流程名", "mermaid": "Mermaid flowchart 代码"}],
  "todos": ["后续待办或明日计划，可为空数组"]
}

规则：
1. 忠实原文，不编造、不夸大。
2. 只有内容中存在清晰流程/逻辑关系时才生成 flowcharts，最多 2 个，节点文字简短。
3. 无法判断的字段用空数组或空字符串。
```

**周报生成提示词**（`report.rs::REPORT_SYSTEM`）：输出四板块（`本周完成事项` / `关键成果·亮点` / `问题与风险` / `下周计划`）Markdown，忠实不夸大，要点列表（`- ` 开头），无内容写「无」。

**图片识别提示词**（`parser.rs`）：识别图片文字；若含流程图/架构图/时序图，用 Mermaid 语法描述。

## 7. 编码规范

- **Rust**：扁平模块（每个能力一个 `.rs`）；命令参数/返回用 serde 结构体（`#[serde(rename_all = "camelCase")]` 对齐前端）；统一 `Result<T, String>`（**未引入** thiserror）。
- **前端**：函数组件 + Hooks（`useState`/`useEffect`）；类型与后端对齐（`src/types.ts`）；UI 用 CSS 变量（`--brand` 等，见 `styles.css`）。
- **提交信息**：`feat/fix/docs/chore: 描述`，中文描述。
- **数据兼容**：JSON 带 `version` 字段；settings 旧结构通过 `LegacyWebdavConfig` 在 `load()` 时自动迁移。
- **密钥**：优先 Keychain，失败降级明文，二者都保证功能可用。

## 8. 开发环境搭建

```bash
# 1. 依赖：Rust（rustup，国内可配 rsproxy 镜像）+ Node 20+ + Xcode Command Line Tools
#    rustup 加速：export RUSTUP_DIST_SERVER=https://rsproxy.cn
#    cargo 加速：~/.cargo/config.toml 配置 rsproxy 源

# 2. 安装前端依赖
npm install

# 3. 运行
npm run tauri dev      # 开发（Vite 热重载前端 + cargo 重编译后端）
npm run tauri build    # 打包 .app / .dmg（打包前需在 tauri.conf.json 开启 bundle）

# 4. 纯前端/后端单独检查
npm run build          # tsc + vite build
cd src-tauri && cargo check
```

**关键依赖**（`src-tauri/Cargo.toml`）：

| 依赖 | 用途 |
|---|---|
| `tauri 2` / `serde` / `serde_json` / `uuid` | 框架与序列化 |
| `reqwest 0.12`（rustls-tls） | LLM API 与 WebDAV HTTP 客户端 |
| `tokio 1`（rt-multi-thread, macros, time） | 异步运行时 |
| `chrono` / `dirs` | 时间 / 数据目录 |
| `zip` + `quick-xml 0.31` | docx 解包解析 |
| `pdf-extract 0.7` | PDF 文本提取 |
| `base64` | 附件 / 图片 base64 |
| `keyring 2` | macOS Keychain |
| `md5 0.7` | WebDAV Digest 认证摘要 |

**前端依赖**：`@tauri-apps/api 2`、`react 18`、`react-dom`、`mermaid 11`；构建 `vite 5` + `typescript 5`。

**LLM API 兼容性**：记录转化/周报走 `/chat/completions`（OpenAI 兼容）；视觉模型走多模态消息（`image_url`）。本地 Ollama 地址 `http://localhost:11434/v1`。

## 10. 功能迭代机制

1. **需求变更**：先改 `docs/需求规格说明书.md`（记版本、日期、变更点）。
2. **技术落地**：同步更新本文档对应模块（数据模型 / Prompt / 模块设计）。
3. **实现**：按里程碑拆任务，提交关联文档版本。
4. **回看**：本文档 + PRD 为唯一事实来源，代码以文档为准对齐。
