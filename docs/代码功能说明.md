# WorkTrace 代码功能说明

> 面向开发者 / 维护者的详细代码结构与功能说明文档。本文档说明各模块的职责、前后端命令约定、数据模型与关键实现。

## 一、整体架构

WorkTrace（工作日迹）是一个 **Tauri 2 桌面应用**，采用 Rust 后端 + Web 前端（React 18 + TypeScript + Vite）架构，使用纯粹的**文件化 JSON 存储**（无数据库），数据根目录为 `~/Library/Application Support/WorkTrace/`。

```
┌─────────────────────────────────────────────┐
│  Web 前端（React 18 + TS + Vite）            │
│  views(Dashboard/Report/Settings)           │
│  components(InputBox/Heatmap/Calendar/...)  │
│  api(Tauri invoke 封装)                     │
└──────────────┬──────────────────────────────┘
               │  Tauri IPC（invoke / 事件）
┌──────────────▼──────────────────────────────┐
│  Rust 后端（src-tauri/src）                  │
│  lib.rs(命令注册/生命周期/托盘/同步调度)       │
│  ai.rs(storage.rs  parser.rs  report.rs     │
│  settings.rs  sync.rs)                      │
└──────────────┬──────────────────────────────┘
               ▼
   文件系统(records/reports/settings JSON) + Keychain
```

## 三、数据模型（storage.rs）

### RecordEntry（单条记录）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | String | UUID 唯一标识 |
| kind | String | `record`=工作记录，`todo`=待办 |
| createdAt / updatedAt | String | RFC3339 时间戳 |
| rawText | String | 原始输入文本 |
| sourceAttachments | Vec<String> | 来源附件（一次性原料） |
| modelUsed | String | 使用的大模型 id |
| status | String | `confirmed` 等状态 |
| structured | Structured | AI 结构化结果 |

### Structured（结构化字段）

采用「新字段为主、旧字段兼容」的设计，保留旧字段做历史数据向后兼容（`#[serde(default)]` 保证旧 JSON 能正常加载）。

| 字段 | 类型 | 说明 |
|---|---|---|
| records | Vec\<RecordField\> | **新字段**：工作记录条目 |
| todoItems | Vec\<TodoField\> | **新字段**：待办条目 |
| summary / tasks / tags / outputs / flowcharts / todos | 旧字段 | 历史数据兼容，`serde(default)` |

#### RecordField（工作记录条目，对应职场助理提示词）

| 字段 | 说明 |
|---|---|
| time | 时间（日期/时间段），未提及为"无" |
| content | 工作内容 |
| progress | 进度/结果（完成状态、产出） |
| people | 相关人员/部门 |
| next | 备注/下一步 |

#### TodoField（待办条目，对应日程秘书提示词）

| 字段 | 说明 |
|---|---|
| timeLocation | 时间地点 |
| item | 待办事项 |
| note | 注意点/提醒 |

### DayRecord（每日文件）

```rust
pub struct DayRecord {
    pub version: u32,      // 版本号
    pub date: String,      // YYYY-MM-DD
    pub entries: Vec<RecordEntry>,
}
```

每日期文件路径：`records/YYYY/MM/YYYY-MM-DD.json`。

## 四、后端模块详解

### 4.1 lib.rs — 生命周期与命令入口

- **数据根目录**：`data_dir()` 返回 `~/Library/Application Support/WorkTrace/`，自动建目录。
- **托盘驻留**：系统托盘 + 关闭窗口拦截。`.on_window_event` 拦截 `CloseRequested` 调 `api.prevent_close()` + `window.hide()`；托盘菜单含「打开主窗口 / 退出」，只有「退出」才 `app.exit(0)` 真正退出（退出前会走同步逻辑）。
- **定时同步调度**：启动 3 秒后首次同步；之后每 60 秒检查，累计到配置间隔触发同步。
- **命令注册**：`tauri::generate_handler!` 注册所有前端可调用的后端命令。
- **退出同步**：`RunEvent::Exit` 时尽力同步，限 10 秒防阻塞卡死。

### 4.2 ai.rs — 大模型调用与提示词转化

- `chat_completion(model_id, system, user)`：通用 OpenAI 兼容对话调用。先带 `temperature=0.3`，部分推理模型（如 kimi-k3）只允许 `temperature=1`，若返回 400 会去掉 temperature 重试。
- `transform_record(input, model_id)`：工作记录转化，用**职场助理**提示词，返回 `Vec<RecordField>`。
- `transform_todo(input, model_id)`：待办转化，用**日程秘书**提示词，返回 `Vec<TodoField>`。
- 输出为纯文本格式（`### 记录 N` / `### 待办 N`），解析器：
  - `split_blocks(content, title)`：按 `### 标题` 切块，去掉标题行。
  - `split_kv(line)`：拆「字段：值」，`char_indices` 兼容中英文冒号。
  - `parse_record_text` / `parse_todo_text`：提取每块的字段行。
- `test_model(model)`：连通性测试，发最小请求。

两类提示词的核心区别：

| | 工作记录 | 待办 |
|---|---|---|
| 角色 | 职场助理 | 日程秘书 |
| 分块标题 | `### 记录 N` | `### 待办 N` |
| 字段 | 时间/工作内容/进度结果/相关人员/备注下一步 | 时间地点/事项/注意点 |

### 4.3 parser.rs — 附件解析

- `parse_docx`：zip 解包 + quick-xml 提取 `word/document.xml` 的 `<w:t>` 文本。
- `parse_pdf`：写临时文件后用 `pdf-extract` 提取文本。
- `parse_image`：图片走内置 PaddleOCR 多模态识别（讯飞免费 OCR 服务，开箱即用）。

### 4.4 storage.rs — 数据模型与 CRUD

- `read_day(date)` / `write_day(record)`：读写每日 JSON 文件。
- `confirm_record(date, raw_text, model_id, records)`：把 AI 转化的多条工作记录入库。
- `confirm_todo(date, raw_text, model_id, todo_items)`：入库待办；若待办为空则**兜底按行拆分原文**。
- `delete_entry(date, entry_id)`：删除某条记录。
- `update_entry(date, entry_id, structured)`：更新某条记录的结构化内容。
- `get_month_active(month)` / `get_year_active(year)`：统计每月/每年每天记录数与待办数，供日历/热力图使用。

### 4.5 report.rs — 周报

- `generate_report(week_start, model_id)`：汇总本周 7 天记录 → 发给 AI → 生成四板块周报（完成事项/关键成果/问题风险/下周计划）→ 保存 `reports/YYYY-Www.md`。
  - **智能分类提示词**：汇总时在开头注明「本周日期范围」，待办保留时间地点并标「来源：待办」，AI 结合时间+语义判断归属（本周内活动归本周完成事项，未来安排才进下周计划）。
- `get_report(week_start)`：读取某周已保存周报。
- `save_report(week_start, content)`：保存/覆盖编辑后的周报内容。
- `export_report(content, week_start, format)`：导出 Word（`.doc` HTML）/ PDF（`.html` 可打印）。

### 4.6 settings.rs — 配置管理

- 大模型配置（`ModelConfig`：id/name/baseUrl/model/apiKey/role/isDefault）；密钥存 Keychain。
- WebDAV 账号（`WebdavConfig`：多账号数组 + 备份设置）。
- `get_backup_settings` / `save_backup_settings`：同步间隔、附件保留天数。

### 4.7 sync.rs — WebDAV 备份同步

- 多账号模式：`webdavAccounts` 数组 + 全局 `backup` 设置，支持测试/设为默认/切换。
- 认证：**Basic + Digest 自动切换**（坚果云 Basic、中国科技云 Digest）。
- 首次同步自动建目录，仅同步结构化记录与周报，附件不同步。

## 五、前端模块详解

### 5.1 api/index.ts — Tauri IPC 封装

统一封装所有 `invoke` 调用，前端组件不直接接触 Tauri API。同时导出前端事件常量：

| 事件 | 说明 |
|---|---|
| `RECORD_CHANGED_EVENT` | 记录入库后触发，日历/热力图刷新 |
| `BACKUP_CHANGED_EVENT` | 备份账号切换后触发 |
| `CHECK_UPDATE_EVENT` | 设置页检查更新按钮触发 |
| `UPDATE_STATUS_EVENT` | 检查更新结果回传（checking/uptodate/available/error） |

### 5.2 views/Dashboard.tsx — 工作台

组合 `InputBox`（统一输入框）+ `Heatmap`（年度热力图）+ `Calendar`（月历）。

### 5.3 components/InputBox.tsx — 统一输入框

- `record`/`todo` 两种模式切换。
- 发送时按模式调用 `transformRecord`/`transformTodo`，展示结构化预览（记录字段卡片 / 待办勾选项）。
- 确认入库后触发 `RECORD_CHANGED_EVENT`。
- 附件拖拽/粘贴（⌘V）通过 `parseAttachment` 处理后追加到输入框。

### 5.4 components/Heatmap.tsx & Calendar.tsx — 可视化

- Heatmap：GitHub 风格年度热力图。
- Calendar：react-calendar 月历，可跨年月切换；记录数与待办数用不同颜色徽标；点击日期弹出 `DetailModal`。

### 5.5 components/DetailModal.tsx — 详情弹窗

- 展示某天的全部记录/待办。
- 支持编辑（按条目增删字段）、删除（二次确认）。
- 优先展示新字段（records/todoItems），旧数据走旧字段兜底。

### 5.6 views/Report.tsx — 周报页

- 上/下一周切换，模型选择，生成/导出/编辑。
- 编辑态：textarea 编辑 Markdown + 保存/取消（调 `saveReport`）。

### 5.7 views/Settings.tsx — 设置页

- `model` tab：大模型增删改查 + 连通性测试。
- `backup` tab：WebDAV 账号配置 + 同步设置。
- `about` tab：版本信息 + 检查更新（带状态反馈）。

## 六、更新机制（updater）

- **流程**：设置页检查更新（或启动 5 秒后自动）→ `latest.json` → 发现新版本 → 顶部横幅「立即更新」→ 下载安装 → 重启。
- **构建**：`tauri.conf.json` 配置 `createUpdaterArtifacts: true` + updater 端点；GitHub Actions 打 tag 自动打包产出 `.app.tar.gz/.sig`、`.exe/.sig`、`latest.json`。
- **权限**：`capabilities/default.json` 含 `updater:default` 权限；前端用 `@tauri-apps/plugin-updater`。

## 七、关键命令行

```bash
npm install                    # 安装前端依赖
npm run tauri dev              # 开发运行（Vite + Rust 编译 + 弹出窗口）
npm run tauri build            # 打包 .app / .dmg / .exe
npm run tauri signer generate  # 生成更新签名密钥
```

> 国内网络：npm / cargo 可配镜像加速；更新端点指向 GitHub Releases。
