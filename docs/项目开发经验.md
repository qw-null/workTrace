# 工作日迹（WorkTrace）项目开发经验总结

> 记录「工作日迹」从 0 到可分发版本（v0.1.1）过程中积累的技术选型、架构决策与踩坑经验，供后续迭代复用。

## 一、技术栈与关键架构决策

| 项 | 选择 | 理由 |
|---|---|---|
| 桌面框架 | **Tauri 2**（Rust + React 18 + TS + Vite） | 包体小（对比 Electron）、前后端类型统一、Rust 后端性能好 |
| 前端状态 | React `useState` | 应用规模不大，**不引入 Zustand/Redux**，保持轻量、减少心智负担 |
| 数据存储 | **纯文件化 JSON**（`records/YYYY/MM/YYYY-MM-DD.json`） | 本地优先、人类可读、易备份/迁移/同步；**不用 SQLite**（避免依赖和锁问题） |
| 错误处理 | `Result<T, String>` | 全项目统一用字符串错误，**不引入 thiserror**，够用且简单 |
| 流程图 | Mermaid 懒加载 | 按需加载，避免首屏体积膨胀 |
| 数据根目录 | `~/Library/Application Support/WorkTrace/` | 平台标准数据目录，`dirs::data_dir()` 定位 |

**核心设计原则**：入口做到零摩擦（一句话/粘贴），出口做到一键交付（周报/导出），中间的 AI 结构化、可视化、同步都围绕「随手记、自动整理」这条主线。

## 二、核心功能实现经验

### 1. AI 结构化记录
- 协议走 **OpenAI 兼容** `/chat/completions`，同时支持 **Ollama 本地**（同构，只是 base_url 不同）。
- 模型可配置多个，用 `role` 区分用途：`record`（记录转化）、`report`（周报）、`vision`（图片识别，后被内置 OCR 取代）。
- **Schema 稳定性的三件套**：
  1. 强化 System Prompt，明确 `tasks/tags/outputs/todos` 必须是字符串数组、禁止对象；
  2. 后端 `Structured` 各字段加 `#[serde(default)]`，缺字段不崩；
  3. **self-correction**：首次解析失败时，把错误信息反馈给模型重试一次。

### 2. 附件解析与 OCR
- **docx** = zip 解包（`zip` crate）+ `quick-xml` 提取 `w:t` 文本。
- **pdf** = `pdf-extract` 提取文本（扫描件无文本，需走图片 OCR）。
- **图片 OCR**：最初用 macOS 原生 Vision（swift 脚本 + `swiftc` 编译缓存），后统一改为**讯飞 PaddleOCR 大模型内置**（`image_url` 多模态 + Bearer 认证），实现跨平台一致、无需用户配置。

### 3. 记录 / 待办分离
- `RecordEntry` 加 `kind` 字段（`record` / `todo`），旧数据用 `#[serde(default = "default_kind")]` 兼容为 record。
- 待办不经过 AI 结构化，按行拆分直接入库（`confirm_todo`）。
- 日历用 `DayActive{count, todo_count}` 区分计数，前端蓝（记录）/橙（待办）双色徽章。

### 4. WebDAV 多账号备份与同步
- 多账号数组 + 全局备份设置，支持测试/设为默认/切换。
- 认证 **Basic/Digest 自动切换**：先试 Basic，收到 401 且 `WWW-Authenticate: Digest` 时改用 Digest 重试（坚果云 Basic、科技云 Digest）。
- `reqwest` 加超时（connect 10s + timeout 30s），避免网络异常卡死 UI。
- 首次同步远端目录不存在（404）时自动 `MKCOL` 建目录。
- **双向增量同步**：按 mtime 比较，上传「本地新/更新」，下载「远端新/更新」。

### 5. 打包发布（GitHub Actions）
- macOS 出 `.app` + `.dmg`；Windows 走 GitHub Actions 出 NSIS `.exe`。
- release workflow：matrix 双平台 `tauri build` → upload-artifact → release job 发布。

## 三、踩坑记录（最有价值的经验）

### 坑 1：Tauri 2 里 `window.confirm`/`alert` 不工作
**现象**：删除功能「点了没反应」。
**根因**：Tauri 2 的 WebView（WKWebView）默认不实现原生 `confirm`/`alert`/`prompt`，`window.confirm` 直接返回 `false`。
**解决**：改用界面内联二次确认（点「删除」→ 变「确认删除」+「取消」）。系统级对话框应走 `@tauri-apps/plugin-dialog` 的 `ask`/`confirm`。

### 坑 2：`Path::join` 遇绝对路径会替换基路径
**现象**：科技云盘同步报 `Read-only file system (os error 30)`。
**根因**：科技云 PROPFIND 返回的 href 是完整 URL 且带双斜杠（`.../worktrace//records/...`），解析出的相对路径以 `/` 开头；`data_dir().join("/records/...")` 被当成绝对路径，写到了系统根目录（只读）。
**解决**：`href_to_rel` 用 `trim_matches('/')` 去掉前后斜杠，保证永远是相对路径。

### 坑 3：`serde(rename_all = "camelCase")` 遗漏导致字段对不上
**现象**：日历待办标记一直显示 0。
**根因**：后端 `DayActive.todo_count` 没加 `rename_all`，序列化成 `todo_count`，前端读 `d.todoCount` 拿到 `undefined`。
**解决**：结构体补 `#[serde(rename_all = "camelCase")]`。教训——**前后端字段命名约定要统一，后端 struct 逐个确认 rename 规则**。

### 坑 4：推理模型对 `temperature` 有限制
**现象**：kimi-k3 报 `invalid temperature: only 1 is allowed for this model`。
**根因**：代码硬编码 `temperature: 0.3`，而推理模型只接受 `1`。
**解决**：先带 `0.3` 请求，若 400 且 body 含 `temperature`，自动去掉该参数重试一次（普通模型不受影响）。

### 坑 5：推理模型不严格遵守 JSON Schema
**现象**：kimi-k3 返回 `tasks` 是对象数组、缺字段，反序列化失败。
**解决**：① 强化 Prompt 明确类型；② `serde(default)` 容错缺字段；③ 解析失败时 self-correction 重试。

### 坑 6：未签名应用反复弹钥匙串授权框
**现象**：测试/同步老是弹「使用钥匙串中的机密信息」。
**根因**：未签名/ad-hoc 签名的应用每次重编译签名都变，macOS 无法记住授权。
**解决**：密码改存**本地文件**（`settings/secrets.json`），彻底不碰钥匙串。配合内存缓存，进程内第一次读后不再读文件。

### 坑 7：GitHub Actions release 产物没上传
**现象**：release 创建了但里面没有 dmg/exe。
**根因**：`softprops/action-gh-release` 的 `files: *.dmg *.exe` 只匹配当前目录，而 `upload-artifact` 保留了完整目录层级，文件在子目录里匹配不到。
**解决**：release job 先 `find ... -exec cp {} . \;` 把安装包平铺到根目录，再发布；并把 `draft` 改为 false 直接发布。

### 坑 8：macOS dmg 打包 hdiutil 尺寸 bug
**现象**：本地打 dmg 报「设备上无剩余空间」。
**解决**：`hdiutil` 显式传 `--disk-image-size`。

### 坑 9：中文产品名/路径的兼容问题
- macOS 产品名用英文 `workTrace`（避免中文文件名在打包/CI 出问题），`window.title` 保留中文。
- WiX3 不支持中文产品名 → Windows 打包跳过 msi，只用 NSIS exe。

### 坑 10：页面切换导致输入内容丢失
**现象**：输入框内容切到设置再回来就没了。
**根因**：条件渲染 `{page === "dash" && <Dashboard />}` 卸载了组件，`useState` 状态归零。
**解决**：输入草稿用 `localStorage` 持久化，挂载时恢复、输入时实时保存、入库成功后清除。

### 坑 11：科技云盘 Digest 认证细节
- 账号要**邮箱格式**，密码要用「客户端访问 → WebDAV」里单独设置的**应用密码**，不是登录密码。
- Digest 挑战要正确解析 `realm/nonce/qop/opaque`，`nc` 每次 401 挑战固定 `00000001`（伴随全新 nonce）。

## 四、可复用的方法论

1. **「记录 → 结构化 → 回顾 → 导出」流水线**：这条链路可以迁移到会议纪要、读书笔记、客户跟进等场景。核心两点——入口零摩擦，出口一键交付。
2. **AI 输出的健壮性三件套**：强化 Prompt 约束类型 + `serde(default)` 容错 + self-correction 兜底，比单纯调 prompt 可靠得多。
3. **配置不硬编码**：API Key、WebDAV 密码等敏感信息不写进代码/GitHub，存本地文件或运行时注入。
4. **改动顺序**：需求变更遵循「改 PRD → 改开发文档 → 改代码」，文档是唯一事实来源。
5. **遇到「点一下没反应」**：先怀疑 WebView 环境差异（如 `window.confirm`）、字段命名不匹配（serde rename）、路径拼接（`Path::join`），往往不是业务逻辑错，而是平台/序列化层面的坑。
